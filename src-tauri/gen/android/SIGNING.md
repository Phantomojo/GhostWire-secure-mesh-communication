# Android Signing Configuration for GhostWire

## Overview

GhostWire uses two signing configurations:
- **Debug** — for development builds (auto-generated by Android SDK)
- **Release** — for Play Store distribution (requires manual keystore generation)

## Debug Keystore

Android SDK auto-generates a debug keystore at:
```
~/.android/debug.keystore
```

Default credentials:
- **Password:** `android`
- **Key alias:** `androiddebugkey`
- **Validity:** 30 years

Debug builds are signed automatically when running from Android Studio or using `./gradlew assembleDebug`.

## Release Keystore Generation

### Generate a new keystore

```bash
keytool -genkeypair \
  -v \
  -keystore ghostwire-release.jks \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000 \
  -alias ghostwire
```

You will be prompted for:
- Keystore password (use a strong password)
- Key password (can be same as keystore password)
- First and last name
- Organizational unit
- Organization
- City
- State
- Country code (2 letters)

### Store credentials securely

Add to `~/.gradle/gradle.properties` (never commit this file):
```properties
RELEASE_STORE_FILE=/path/to/ghostwire-release.jks
RELEASE_STORE_PASSWORD=your_keystore_password
RELEASE_KEY_ALIAS=ghostwire
RELEASE_KEY_PASSWORD=your_key_password
```

## Play App Signing (Recommended)

Google Play App Signing is the recommended approach for Play Store distribution.

### How it works

1. You upload a signed APK/AAB to Play Console
2. Google re-signs it with their managed key
3. Your upload key is separate from the app signing key
4. Google handles key rotation and security

### Setup

1. In Play Console, go to **Setup → App signing**
2. Enroll in Play App Signing
3. Generate an upload key (separate from signing key):

```bash
keytool -genkeypair \
  -v \
  -keystore ghostwire-upload.jks \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000 \
  -alias upload
```

4. Export the public key for Play Console:

```bash
keytool -export -alias upload \
  -keystore ghostwire-upload.jks \
  -file ghostwire_upload.pem \
  -storepass your_password
```

5. Upload the `.pem` file to Play Console

### Benefits

- Google manages the app signing key
- Automatic key rotation support
- Key upgrade from v1 to v2/v3 signing
- No risk of losing your signing key

## Self-Managed Signing

Use this if you need full control over the signing key.

### Configure in build.gradle

In `app/build.gradle`, add:

```groovy
android {
    signingConfigs {
        release {
            storeFile file(System.getenv("RELEASE_STORE_FILE") ?: "ghostwire-release.jks")
            storePassword System.getenv("RELEASE_STORE_PASSWORD") ?: ""
            keyAlias System.getenv("RELEASE_KEY_ALIAS") ?: "ghostwire"
            keyPassword System.getenv("RELEASE_KEY_PASSWORD") ?: ""
        }
    }

    buildTypes {
        release {
            signingConfig signingConfigs.release
            minifyEnabled true
            proguardFiles getDefaultProguardFile('proguard-android-optimize.txt')
        }
    }
}
```

## APK Signature Schemes

Android supports multiple signature schemes. Android 11+ requires v2.

| Scheme | Added in | Required from | Description |
|--------|----------|---------------|-------------|
| v1 | Android 7.0 | Always | JAR signing (legacy) |
| v2 | Android 7.0 | Android 11+ | Full APK signing |
| v3 | Android 9.0 | Android 12+ | Key rotation support |
| v4 | Android 11.0 | Optional | Incremental install |

### Tauri Configuration

In `src-tauri/tauri.conf.json`, configure signing for Android builds:

```json
{
  "bundle": {
    "android": {
      "signing": {
        "keystorePath": "../ghostwire-release.jks",
        "keystorePassword": "",
        "keyAlias": "ghostwire",
        "keyPassword": ""
      }
    }
  }
}
```

Use environment variables for CI/CD:
```bash
export TAURI_SIGNING_PRIVATE_KEY=$(cat keystore-password.txt)
```

## CI/CD Signing

For GitHub Actions, store credentials as secrets:

```
KEYSTORE_BASE64       # base64-encoded .jks file
KEYSTORE_PASSWORD     # keystore password
KEY_ALIAS             # key alias
KEY_PASSWORD          # key password
```

In the workflow:
```yaml
- name: Decode keystore
  run: echo "${{ secrets.KEYSTORE_BASE64 }}" | base64 -d > ghostwire-release.jks

- name: Build release APK
  env:
    RELEASE_STORE_FILE: ghostwire-release.jks
    RELEASE_STORE_PASSWORD: ${{ secrets.KEYSTORE_PASSWORD }}
    RELEASE_KEY_ALIAS: ${{ secrets.KEY_ALIAS }}
    RELEASE_KEY_PASSWORD: ${{ secrets.KEY_PASSWORD }}
  run: ./gradlew assembleRelease
```

## Verify Signing

Check the signature of a built APK:

```bash
apksigner verify --verbose ghostwire.apk
```

View signing details:

```bash
apksigner print-certs ghostwire.apk
```

## Troubleshooting

### "Keystore was tampered with"
- Wrong password or corrupted keystore
- Regenerate the keystore if password is lost

### "keytool error: java.io.FileNotFoundException"
- Keystore path is incorrect
- Check `RELEASE_STORE_FILE` in gradle.properties

### Play Store rejection
- Ensure v2 signing is enabled (required for Android 11+)
- Upload key must be enrolled in Play App Signing
- AAB format recommended for Play Store (not APK)

### Lost signing key
- If using Play App Signing: contact Google support
- If self-managed: you cannot update the app (must publish as new app)
- Always back up keystores securely
